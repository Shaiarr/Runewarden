# Runewarden 0.9.3

This development update fixes action and crop icons, farming countdowns and HUD resizing. Quest walkthroughs move to Quest Helper while Runewarden retains quest planning.

## Behavior

- Action progress carries native item, spell or skill images for its observed action. Confirmed recipe output and resource identities take precedence over a generic skill reference. Ambiguous animation evidence does not establish a specific resource.
- Farming cards use crop-specific icons. Palm and Curry show their own native saplings rather than a generic fruit-tree image. Icons appear in both radial and text layouts.
- Growing-patch estimates use the native Time Tracking account cycle offset and precision when known. Earlier observations of the same crop stage are retained instead of restarting a whole-stage countdown on every visit. Labels use hours and minutes. With no adequate cycle observation, the remaining growth window remains an estimate. Disease and growth skips can alter the actual ready time; an elapsed estimate does not mark an unobserved patch harvestable.
- Hold Ctrl and left-drag the edge or corner of a Runewarden HUD card to resize it. The gesture scales its content and returned bounds together between 60% and 180%. Alt-drag still moves floating cards. Farm and resource-node cards remain anchored to their scene objects and share their module's size. Character layouts retain the chosen sizes; reset restores positions and sizes. Lock, focus loss and profile changes cancel an active resize, and resize mouse events do not reach game interactions.
- Quest selection opens the external Quest Helper. Runewarden retains quest status, requirements, optimal regular-account ordering, completed-quest filtering and planning links. Quest walkthrough payload is removed from the shipped data, with a metadata-only runtime guard; stage/branch following, dialogue/interaction overlays and quest-owned routes are removed. Training, minigame and boss guides remain.
- The development client includes unchanged Quest Helper 4.18.0 from official Hub marker commit `5f791937a99a676f23c02aa48c4e4d5b50e7edad`, together with the existing pinned Shortest Path companion. The Quest Helper adapter is in the launcher; the main Runewarden Plugin Hub JAR has no typed Quest Helper dependency or bundled Quest Helper classes. Companion features do not count as independent Runewarden implementations in the capability comparison.
- Boss lessons arm exit tracking only after observed arena entry. Known instance/template regions, native Gauntlet/CoX/ToB membership and sourced ToA room/status observations, or a nearby matching boss and reachable bounded chamber provide that evidence. Leaving a supported arena or local-player death clears the selected lesson, coaching HUD, owned markers and route. Pre-entry selection, loading and NPC death/despawn do not clear a lesson. Finite collision chambers are bounded to 1,600 tiles and memoized. Open outdoor areas use observed region/plane exit; ToA retains its guide through internal rooms and waits three valid missing-observation ticks before exit. Its named boss guides use actual boss rooms, including Zebak rather than the Crondis puzzle region. Sotetseg retains its maze lesson and closes at native raid exit or the next sourced boss room. Marker coverage is not universal doorway/phase support; see `boss-arena-source-notes.md`.
- The development launcher starts the bundled Shortest Path companion when Runewarden is active or re-enabled, using the public plugin manager on Swing's event thread. The main Hub JAR's native-plugin activation boundary remains unchanged. Supported guide preparation travel is automatic, waits for client/receiver readiness and has no separate route button. The first request binds the active RuneScape profile even before the travel module's first tick; generation/account guards discard stale work. Pending requests resume when travel becomes available and restore once after its module restarts. An external route change or clear suppresses pending reassertion. Sourced entry-point data supplies actual shipped destinations; method/combat standing instructions and unsupported or ambiguous locations remain unrouted. A catalogue of 545 non-quest guides does not imply 545 verified destinations.
- The guide travel catalogue contains 94 sourced arrival points: 20 minigame locations for 29 guide IDs and 74 training locations for 83 guide IDs. Only authored `prepare`, `preparation` or `travel` sections use them. RuneLite 1.13.2 world-map references, the pinned Shortest Path transport tables and pinned Quest Helper source provide exact retained source lines and coordinates. Portable processing, unsourced destinations and boss/wave standing instructions receive no guessed fallback. Farming route destinations are a separate workflow.
- Active farm runs route to the first unfinished stop on start/resume and advance after manual or native-confirmed stop completion. Saved user pins take precedence, then actual visible scene anchors, then native RuneLite 1.13.2 farm-area markers. Sixty sourced marker sites cover 97 of 107 native patches by exact patch type/region identity; combined markers identify a farm area rather than every plot's exact tile. Eight compost bins, the Etceteria spirit tree and Hespori lack a matching native marker and need an observed anchor or saved pin. Unavailable routes retry after five ticks; a travel-module restart restores the accepted endpoint once. Manual route changes suspend automatic requests until an explicit start/resume; pause, global End run, profile changes and the last stop clear owned routes and invalidate queued starts/completions. This workflow is separate from guide arrival data; the birdhouse guide uses its sourced Verdant Valley arrival rather than pretending to have a native patch workflow.

## Verification

The final build passed 1,505 Java tests in 182 suites and 32 Python parser/audit tests, with no failures or skips. Production outputs were rebuilt from a clean project, the full suite was rerun on the final source, and all 1,436 source/dependency inputs stayed unchanged during verification. Details are recorded in `automated-evidence-0.9.3.json`. Tests cover native farming-clock alignment, rendered action/crop icons, resize input and persistence, quest handoff and the absence of Runewarden quest walkthroughs. Boss lifecycle cases cover passive pre-entry, loading, same-region chamber exit, native membership, between-kill persistence and local death. Routing cases use an unchanged shipped Giants' Foundry guide with its sourced destination and the actual bundled Shortest Path pathfinder, plus readiness, profile, restart and manual-replacement cases. The existing End run regressions remain part of the full suite.

The source pin, companion resources and licenses, explicit launch classpaths, tested classes, pinned native dependencies and Windows runtime remain release checks. The broad capability audit retains its 151-plugin comparison baseline and records partial and missing specialist features.

Windows execution and logged-in behavior remain unverified until actual live acceptance is recorded. The ten live/review gates remain open, including named Quest Helper handoff and compatibility. Plugin Hub review remains pending.
