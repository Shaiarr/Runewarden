# NPC hover sight

Hold **Shift** while hovering a loaded NPC in the game scene to display a black-and-gold sight card beside the pointer and a line to the target. The card shows the NPC name, player-to-NPC sight, NPC-to-player sight and footprint distance. Release Shift to clear the hover. No sidebar selection or click is required. Enable **Always show mob hover** in HUD settings or RuneLite configuration for constant hover; the existing **Mob hover sight** switch still disables hover entirely.

NPC and skilling-resource cards share a dedicated highest-priority **ALWAYS_ON_TOP** overlay. Cards are measured before placement on their first frame, placed above the pointer, and clamped inside all four canvas edges. Oversized lines wrap by measured pixel width, including long words; excessive height is bounded to complete visible rows. The scene's LOS line remains on its original scene layer. Opening a context menu suppresses the card, and each card submission is consumed once so leaving a hover, logging out or changing scene cannot retain a stale box. No settings belonging to other plugins are changed.

The same card now includes a bundled monster reference: documented attack styles, elemental weakness and percentage, the lowest **melee defence bonus**, and static **Usual protection**. Shift also expands magic defence bonus, ranged defence bonuses by ammunition weight and common monster attributes; always-on mode shows the compact reference until Shift is held. Lowest bonus is labelled as a bonus, not a best-weapon or DPS recommendation: levels, equipment, special immunities and mechanics can change the useful attack choice. Actual elemental vulnerabilities remain separate from these comparisons. Mixed attack styles, typeless attacks, magical melee and prayer-penetrating attacks retain their source descriptions. Disable **Mob combat reference** to retain the LOS card without combat facts.

The snapshot contains **2,860 variant records covering 2,817 NPC IDs** from the OSRS Wiki DPS calculator, retrieved on 16 October 2026. Its last monster-data commit is `a27fc3c898eb15accbfa0457c89b6b6a1b132f1f`, dated 2 September 2026. The current transformed NPC ID selects the variant. Where multiple records share an ID, the reference combines descriptions and labels differing bonuses or elemental vulnerabilities as variable; calculator consumers receive no exact base stats if size, magic level or magic attack bonus disagree. NPCs missing an exact ID can use a clearly labelled name match across documented variants. Uncatalogued names retain the LOS card with explicit unavailable facts. The data is loaded and indexed once; hovering issues no HTTP requests and does not rebuild the index.

**Open last NPC on Wiki** in Sight Lab opens the Wiki's native NPC-ID lookup only after the button is clicked. Dataset provenance, adaptations and separate Wiki/upstream licences are bundled in `src/main/resources/com/runewarden/licenses/mob-knowledge-*`.

**Usual protection** is fixed encyclopaedic information for the monster family: documented pure melee, ranged or magic attackers map to the corresponding protection prayer. Mixed families list the actual combination, including all three styles where documented. Typeless and fully prayer-penetrating attacks explicitly state that protection is ignored. Known partial protection and phase-dependent exceptions are supplemented from revision-pinned Wiki references listed in the data. For example, Bloodveld and Jelly use melee protection despite their magic-based accuracy, Kraken attacks ignore protection, Vardorvis provides only partial melee protection, and Zulrah is labelled with ranged, magic and typeless attacks rather than a single overhead.

No upcoming-attack inference, animation analysis, current-attack selection, prayer-change alert or game action is performed. Jagex's [third-party client guidelines](https://secure.runescape.com/m=news/third-party-client-guidelines?oldschool=1), checked on 16 October 2026, include a broad restriction on indicating prayers in combat. They do not provide a specific ruling on this static Wiki-style presentation. This implementation's Plugin Hub acceptance is therefore unresolved and must be reviewed; it is not represented as approved.

The native top menu entry supplies the hovered NPC. When **Walk here** is the top scene action, NPC entries beneath it are inspected too, so right-click-only Attack and shift-walk settings retain hover sight. Widgets, objects and ground-item top entries still suppress underlying NPCs. Open context menus, other non-NPC top entries, a pointer outside the canvas, logging out, despawns, reused actor indices, another WorldView or plane, and unavailable collision data clear the hover reading. Strict NPC menu-action validation also guards the public index fallback.

Measurements use RuneLite `WorldArea.hasLineOfSightTo` in each direction, preserving their documented asymmetry and the actor's actual WorldView. Footprints are used rather than assuming a single target tile. A clear sight line does not determine attack range, attack type, aggression or whether a monster can path around an obstacle; the card consequently makes no guaranteed safe-spot claim and does not search for optimal tiles, predict mechanics or perform game actions.

Disable **Mob hover sight** to use the existing manual target selector in **Sight Lab**. The previous manual target can be restored when hover is disabled; leaving a hovered NPC does not silently pin it.

The implementation uses the pinned RuneLite 1.13.2 public APIs. RuneLite's [rejected features](https://github.com/runelite/runelite/wiki/Rejected-or-Rolled-Back-Features) and [MenuEntry API](https://static.runelite.net/runelite-api/apidocs/net/runelite/api/MenuEntry.html) were checked on 16 October 2026. Plugin Hub acceptance remains subject to review.
