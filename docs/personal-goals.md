# Personal goals

Runewarden's **Goals** sidebar stores a separate progression queue for each RuneScape character. Skill goals accept a level from 2 to 99 or an exact XP total up to 200 million. Quest goals link to the bundled quest guide. Add several goals, edit them, move them up or down, archive finished tracking, restore an archived goal, or remove it outright.

The opening page prioritises the queue and its summary. **Add goal** opens a separate full-width editor with skill, target, effort and method; **Back** returns to the queue. Personal rate, budget, weekly hours and milestone spacing live under the collapsed **Options** control. Empty and single-page queues have no pagination controls. Archived-goal filtering appears only when relevant.

Skill goals select AFK, Normal or Intensive methods from the shared Training methods catalogue, including training minigames. The **Open guide** and **XP method** controls connect the chosen method to its guide and activity calculator. Methods without published rate data ask for your observed XP/hour. A reference-rate estimate extrapolates the range applicable at the current observed skill level; it is not a promise that future levels or setups keep that rate. Players can override it with their own rate, add a GP budget and choose weekly play hours. A GP budget is a user-entered planning limit, not a calculated method cost.

Milestones use the game's real level XP thresholds at a configurable interval, plus the exact final XP target. Current XP and quest completion come from the live client; reaching a goal is recorded automatically. Manually archiving a goal never fabricates game progress or marks a quest complete.

Typed skill, quest and combat requirements reuse the bundled, sourced guide data. Missing skill and completed-quest prerequisites can be queued in dependency order before the selected goal. Existing equal-or-higher skill goals and existing quest goals are retained. Prerequisite choices, partially-started quest requirements, account-type conditions and unobservable facts remain explicit checks; the planner does not choose a route, infer Kudos, or invent completion. Wiki/RuneLite Recipe for Disaster subquest name differences are normalized by identity.

The planner only requests quest states that affect the stored goals and their prerequisite chains. No broad quest polling happens for an ordinary skill goal without quest-dependent methods. Observations are sampled every five game ticks after login warmup. A hidden sidebar does not reconstruct goal cards; ordinary XP changes in unrelated skills do not rerender them. Eight goals appear per page, and collapsed milestone controls are created only when opened. Data is bounded to 100 goals and stored through RuneLite's profile-specific configuration API. Every delayed UI mutation carries the exact character profile and generation it displayed, so an old button cannot edit the next character's goals. There is no own file I/O, network request or game-input automation.
