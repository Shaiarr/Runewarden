# Clue juggling timers

The **Clue timers** sidebar and movable `clue-timers` HUD track observed ground scrolls for all six clue tiers, including the elite challenge-scroll exception. Each observed native item keeps its own countdown; identical clue IDs on one tile do not collapse into one timer. The display can show separate rows or only the earliest deadline, with optional countdown rings, game ticks or minutes/seconds, tier filters, configurable expiry notifications, and manual per-row removal or clearing. Route opens the selected observed position through Runewarden's navigation integration.

Timers use `TileItem.getDespawnTime()` against `Client.getTickCount()` in RuneLite 1.13.2. They do not assume every spawned scroll has the one-hour player-drop lifetime: an NPC's short-lived drop keeps its actual native deadline. An unavailable deadline displays `?` and cannot trigger an expiry notification. A newly observed extended native deadline can reset the warning after a pickup and redrop; merely reloading the same item does not restart its timer.

## Scene and account behavior

- Leaving native visibility preserves an observed off-scene timer. Same-tick replacement events at the same ID and position reattach the prior unseen timer; distinct simultaneous native items remain separate. A nearby observed despawn removes the corresponding identity. Revisiting a visible, empty tile also removes an old remembered entry.
- Region loading detaches scene objects and reseeds the native current-plane ground items once per scene/base/plane. Loaded native items refresh their real deadline. Temporary sub-world views are excluded. A top-level instance can show its observed timers, but those entries are discarded on scene loading and are not saved as persistent world loot.
- Only private clue-tier entries are saved for the current RuneLite character profile. Public drops, instances and extra-item timers are not restored as paused private loot. A clean observed logout/hop checkpoint can resume with `~` and **awaiting sighting** status; a native sighting verifies the deadline. No expiry notification is sent from a remembered checkpoint.
- Active sessions write dirty checkpoints. An unclean stop, lost connection, disabled plugin or interrupted process restores `?` until the item is observed again. Offline time is never guessed and a stale checkpoint never restarts a full-hour timer. A subsequent login-screen event cannot upgrade a prior connection-loss checkpoint to clean.
- Changing profiles immediately hides the prior character's snapshots and discards native references. Stale sidebar callbacks cannot route or modify another character's timers. Only Runewarden-owned configuration groups are written.

Extra item rules accept comma-separated IDs, exact names and `*` wildcards. These use the same native, in-session deadlines. Their cross-session pause semantics are deliberately not inferred from those of private clue scrolls. Up to 64 rules and 256 timers are bounded; the HUD shows the earliest eight rows, and the sidebar pages through all tracked rows in groups of twelve. Hidden sidebar panels do not rebuild on game ticks; a showing transition coalesces one refresh from the latest snapshot. The notification setting uses RuneLite's configured desktop/sound delivery. Independent upstream sound channels, infobox-manager placement and its historical timer-reduction multiplier are not implemented. Styling belongs to Runewarden's shared HUD controls.

The tool observes events and offers manually chosen routes. It does not pick up, drop, move to or interact with an item. Native timing accuracy, visibility removal and instance boundaries still need live-client acceptance across scene transitions; this is not a claim of RuneLite review approval.

## Sources and validation

The official Hub marker `clue-scroll-juggling` points to [`geheur/clue-juggling-timers`, commit `c099981f9f8f5f2adea72d1706949b4f461a5f81`](https://github.com/geheur/clue-juggling-timers/tree/c099981f9f8f5f2adea72d1706949b4f461a5f81). Its README is a template; the actual [`ClueScrollJugglingPlugin`](https://github.com/geheur/clue-juggling-timers/blob/c099981f9f8f5f2adea72d1706949b4f461a5f81/src/main/java/com/cluejuggling/ClueScrollJugglingPlugin.java) and [`ClueScrollJugginglingConfig`](https://github.com/geheur/clue-juggling-timers/blob/c099981f9f8f5f2adea72d1706949b4f461a5f81/src/main/java/com/cluejuggling/ClueScrollJugginglingConfig.java) establish the compared capabilities. Runewarden's ledger and HUD are independently implemented and use the newer public native deadlines rather than copying that plugin's older fixed-duration implementation.

The RuneLite 1.13.2 public [`TileItem`](https://github.com/runelite/runelite/blob/runelite-parent-1.13.2/runelite-api/src/main/java/net/runelite/api/TileItem.java), [`Client`](https://github.com/runelite/runelite/blob/runelite-parent-1.13.2/runelite-api/src/main/java/net/runelite/api/Client.java) and [`WorldView`](https://github.com/runelite/runelite/blob/runelite-parent-1.13.2/runelite-api/src/main/java/net/runelite/api/WorldView.java) define the ownership, privacy, native tick deadlines and instance boundaries used here. The OSRS Wiki documents [dropped clue-scroll lifetime and private-item behavior](https://oldschool.runescape.wiki/w/Clue_scroll_(easy)) and [private ground items across logout/hops](https://oldschool.runescape.wiki/w/Drop); the implementation obtains the actual remaining time from the client rather than selecting between conflicting rounded lifetime descriptions.

`ClueJugglingTrackerTest` and `ClueJugglingToolTest` cover native versus unknown deadlines, all tiers, separate stacks, fake respawns, actual pickup, out-of-view expiry, clean/dirty relogs, notification deduplication, instance exclusions, account isolation, profile-safe buttons after full account/key reuse, same-account clearing/key reuse, hidden/showing refresh, bounded sidebar paging, extra-item matching, invalid data, bounds, manual clearing and both HUD modes. Forty-one focused Java tests passed before integration; the integrated suite is recorded separately by the release build.
