# Account progression and diaries

Runewarden shares real account observations between the Goals, Diaries and Account progression modules. The existing skill and quest goals retain their saved identities and behavior. New goal types cover an exact item, a chosen equipment set, an obtained collection-log item, an observed boss kill count, a diary, a Combat Achievement, a music track, an account metric, a supported currency and a supported permanent unlock. A set uses the lowest observed quantity among its explicit pieces. Item goals count only exact selected item IDs; charged/ornamented alternatives are separate choices.

Current item quantities come from the shared OwnershipLedger. The ledger's storage names, timestamps and unknown states remain authoritative: an unopened bank or unseen storage does not establish an absent item. Collection-log ownership is a separate personal fact and is never inferred from owning or buying the item. Only positive entries in the native COLLECTION_TRANSMIT inventory, new-collection game messages, and the game's native collection notification establish obtained items. Opening collection pages gradually adds positive historical observations; unvisited and zero-quantity items remain unknown. This is not a claim that every historic collection slot is available without visiting the game log. The live aggregate count/max is read separately from native collection variables.

Boss kill counts are last observed counts from the game's own `Your … kill count is:` or `Your … completion count is:` messages. Public/player messages cannot establish them. A missing historical observation stays unknown; zero is not manufactured. Account changes and logout immediately hide the previous account's observations. Personally observed collection items and kill counts are stored per RuneScape profile through RunewardenDataStore's guarded, recoverable configuration.

Supported native metrics include Museum Kudos, Rigour, Augury, Arceuus spellbook unlock, Slayer points, Tithe Farm points, Giants' Foundry points, Nightmare Zone reward points, Soul Wars zeal and the three Mixology currencies. Combat Achievement goals reuse the existing module's stable, point/bit-consistent baseline. Music goals reuse the native-definition-aware music module. Spendable currencies and current item/set possession can lose completed status when an authoritative new value falls below the target. Permanent collection, skill, quest and unlock achievements retain completion.

## Diary coverage

`diary-catalog.json` contains all 48 regional/tier diaries and 492 distinct tasks, all with exact native completion observations. The data is adapted from Quest Helper at commit `5f791937a99a676f23c02aa48c4e4d5b50e7edad`; native constants come from the pinned RuneLite 1.13.2 API source. The included generator retains authored instruction text, task locations, 341 shared typed skill references, 164 typed quest references and 784 shared item references, plus route-specific supplies, spellbook/choice/explicit-check requirements and reward descriptions. Native task progress and the tier's reward-claim variable are separate observations. Karamja partial counters are compared using the source's exact predicate; a partial count is not a completion. Three tasks coalesce route variants by their actual completion bit while keeping each route's instructions, supplies and starting stop separately selectable. Only shared requirements are applied to the whole task. Unsupported preparation checks remain marked unknown, including account-type-specific branches; the extractor does not choose an account route.

The Diaries sidebar filters region and tier, hides completed tasks, displays five task cards per page, opens item sources and relevant quest guides, offers a route to the source-authored starting stop, and adds the full diary to the shared goal queue. Tasks advance from native state; no manual checkbox fabricates diary completion. One source task (Morytania Medium Terror Dog) has its instruction delegated to another helper; it opens its pinned source instead of presenting invented instructions. Rewards and longer preparation sections are collapsed.

## Recovery, undo and shared plans

Goal edits, removal, ordering, archive/restore and plan imports have a bounded 20-entry undo/redo history for the current login/profile generation. Automatic progress observation does not create undo entries. Old account buttons cannot edit the next account. A future-version or malformed save is protected by RunewardenDataStore and cannot be overwritten by a routine goal edit.

Shared plans use bounded, validated `RWPLAN1:` data-only codes. Export includes goal definitions, targets and method/preferences, while clearing personal progress, completion times, archive state and identity. Import first shows a preview; applying it binds progress to the current account, skips equivalent existing definitions, checks the 100-goal limit and can be undone in one action. No code, URL or downloaded executable is evaluated.
